# OpenMacroState 中文介绍

OpenMacroState 是一个**可审计、可回到历史当时的全球宏观研究操作系统**。

它要解决的不是“再生成一个宏观观点”，而是让研究者能够检查：某个历史时点
究竟有哪些信息已经公开、数据后来是否修订、哪张资产负债表发生了变化、结论
依赖什么机制、还有哪些竞争解释，以及什么未来观测会证明判断错误。

## 快速运行

```bash
python -m pip install -e '.[dev]'
openmacrostate validate cases/2023-banks
openmacrostate demo cases/2023-banks --reveal reveals/2023-banks --evaluation-at 2023-03-13T22:00:00Z --output build/demo
```

## 首批官方来源切片

项目已经提供首个 pre-alpha 官方数据连接器 `frbny-sofr`，用来捕获纽约联储发布的
SOFR。它不默认联网：离线模式必须显式给出经哈希核验的录制响应，在线模式
必须显式选择 `--online`，两者不能同时使用。连接器也不接受任意 URL，只能
根据起止日期构造预定的纽约联储官方地址。

时间规则故意保守：`effectiveDate` 只说明这个利率对应哪个市场价值日，
不能证明系统何时看到该版本。在线模式使用 core 实际抓取完成时间；离线
recording 里自报的 `retrieved_at` 不是历史可用性证明。若没有独立认证的 proof，
离线回放会用本次 core 回放的 wall-clock 作为可用性上界，receipt 时间只作为
未认证的声明保留。今天抓到的 2018 年数值，或声称在 2018 年抓取的普通录制
文件，都不会被倒填成系统在 2018 年已经捕获的证据。

两种来源状态也不会混写：只有 core 亲自通过固定 HTTPS 路径看到的在线响应才
标为 `core_observed_https`；离线录制一律标为 `unverified_recording`。即使录制
文件自称是完整响应，也只是完整性声明，不是来源签名、历史时间证明或真实历史
案例。

项目同时提供 `treasury-debt-to-penny`，只从美国财政部 Fiscal Data 的固定
Debt to the Penny 地址抓取总公共债务余额。它固定三个来源字段、编码后的日期
过滤、升序、JSON 格式与单页上限；起始日不得早于 1993-04-01，范围最多 367 天。
连接器拒绝空页、截断分页、重复或乱序日期，以及非正的两位小数字符串。请求
结束日和每行日期都必须严格早于 core 抓取时的纽约日历日期。`record_date` 不会
被冒充成精确发布时间，发布、版本与采集时间仍保守使用本次 core 抓取或回放时间。

第三个连接器 `fed-h41-release` 捕获 Fed 官方带日期的 H.4.1 资产负债表 HTML。
当前规则读取总资产、总负债、总资本、持有证券、Primary Credit、财政部一般
账户和准备金余额七个周三存量，单位保留为百万美元。它按表格语义、唯一行名
和明确的 Wednesday 列取值，不依赖表格序号或固定行号；日期、单位、列、行、
数字或页面结构不符合契约时一律拒绝。页面日期与通常所说的周四 4:30 都不能
证明当时实际可用，所以发布、版本和采集时间仍取本次 core 抓取或回放时间。

同一案例还可以运行首个实验性会计校验：

```bash
oms audit accounting build/fed-h41-release \
  --rule fed-h41-balance-sheet-v1 \
  --observed-at 2023-03-15T00:00:00Z
```

它只使用通过案例时间与证据检查的七条观测，并要求它们来自同一来源、同一原始
材料、同一单位和同一观测时点。审计会重新读取本地封存 HTML、复核哈希，并用当前
解析规则重建七条记录；随后以固定 100 万美元容差核对“总资产等于总负债与总资本
之和”。这种重放证明数值来自封存字节，但不证明字节在历史上何时公开。这个命令和
输出仍属 pre-alpha 实验接口，不是稳定会计 schema，也不是通用宏观状态图。详细规则见
[H.4.1 来源契约](../fed-h41-source-contract.md)
与[会计校验说明](../accounting-audit.md)。

同一个封存案例还可以追溯某个派生值的完整上游路径：

```bash
oms trace state build/fed-h41-release \
  --rule fed-h41-balance-sheet-v1 \
  --observed-at 2023-03-15T00:00:00Z \
  --target balance_sheet_residual
```

实验输出把“命题属于事实、推断、预测还是情景”和“数值来自报告、计算、假设
还是模型”分开。本切片只生成七个 `fact/reported` 节点、六个
`fact/derived` 节点和明确标记为非因果的计算依赖边，不会凭空生成推断、预测或
情景。它会继承案例快照、原始材料、解析规则和时间边界，但仍然只是事后重算，
不能证明研究者在 2023 年已经得到该结果。详见[状态追溯说明](../state-trace.md)。

当前项目政策不允许使用 FRED/ALFRED 作为 connector 录制源。它们的版本语义很有用，
但现行条款与本项目所必需的软件开发、存储、归档及可选 AI 分析冲突。项目优先
连接原始官方发布者。详细边界见 [Connector 契约](../connectors.md)和
[数据许可政策](../data-licensing.md)。

当前内置的 `2023-banks` 是完全合成的教学与软件测试夹具，不是真实历史案例。
其中所有数值、标识、结论、预测与结果均为虚构，不能用来判断真实的 2023 年
银行体系。它可离线运行，不需要 AI 服务或 API Key。当前确定性核心实现了
校验和核对、时间截止过滤、证据闭包检查、快照与揭晓后评分；AI 只能作为可选
分析层，不能越过截止时间、伪造证据或把推断冒充观测。更多生产数据连接器、
真实历史证据包和模型适配器仍是后续建设方向；现有 SOFR 与 Treasury 连接器是
经过边界审计的 pre-alpha 切片，H.4.1 连接器也遵守同一保守时间边界；三者都
不是稳定生产系统。

研究包与揭晓包在物理目录和校验清单上完全分开：`validate` 只接收 `cases/` 下的
研究包，不会定位或读取 `reveals/`；`demo` 才显式接收揭晓包和评估时间。系统
区分观测、发布、版本、采集、截止五个时间。`prospective_capture` 要求在截止前
完成采集；`retrospective_authenticated` 允许事后采集，但必须有同一版本在截止
前已发布的可核验凭据。当前合成案例属于后者，不能冒充前瞻采集或真实历史证据。
当前 pre-alpha 只实现了明确标注的合成凭据验证器；真实资料若在截止后才采集，
会直接拒绝，直到项目接入经评审的档案或签名验证器。供分析或 AI 使用的
`snapshot.json` 只含合格记录；隔离值、无效结论及其来源元数据不会混入快照。

默认不覆盖已有输出目录。确需重跑时可在完整命令末尾加 `--force`；它只接受
空目录或属于同一案例、带 OpenMacroState 标记的旧输出，不授权写入研究包或
揭晓包。

## 欢迎哪些贡献

- 官方宏观数据连接器；
- 历史事件回放与事后评分；
- 资产负债表、传导机制和竞争解释；
- 外部宏观模型适配器；
- 测试、复现、数据许可核查；
- 文档、教程、翻译和社区答疑。

贡献者不需要同时精通经济学与软件工程。Issue 会尽量标注所需技能、预计工作量
和验收标准。核心协议或公共模式变更先走 RFC；普通文档修正和现有接口下的
连接器可以直接提交 Pull Request。

## 许可证

项目原创代码与文档默认采用 Apache-2.0。外部数据不会因此自动变成
Apache-2.0：每个来源必须单独说明许可、转载条件和署名要求。权利不清楚时，
只保留官方链接或使用合成测试数据，不把原始数据提交进仓库。

详细规则以英文版 [README](../../README.md)、
[贡献指南](../../CONTRIBUTING.md)、[治理规则](../../GOVERNANCE.md)和
[数据许可政策](../data-licensing.md)为准。
