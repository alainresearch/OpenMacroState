# OpenMacroState 中文介绍

OpenMacroState 是一个**可审计、可回到历史当时的全球宏观研究操作系统**。

它要解决的不是“再生成一个宏观观点”，而是让研究者能够检查：某个历史时点
究竟有哪些信息已经公开、数据后来是否修订、哪张资产负债表发生了变化、结论
依赖什么机制、还有哪些竞争解释，以及什么未来观测会证明判断错误。

## 快速运行

```bash
python -m pip install -e '.[dev]'
openmacrostate validate cases/2023-banks
openmacrostate demo cases/2023-banks --reveal reveals/2023-banks --evaluation-at 2023-03-13T22:00:00Z --output build/demo
```

当前内置的 `2023-banks` 是完全合成的教学与软件测试夹具，不是真实历史案例。
其中所有数值、标识、结论、预测与结果均为虚构，不能用来判断真实的 2023 年
银行体系。它可离线运行，不需要 AI 服务或 API Key。当前确定性核心实现了
校验和核对、时间截止过滤、证据闭包检查、快照与揭晓后评分；AI 只能作为可选
分析层，不能越过截止时间、伪造证据或把推断冒充观测。生产数据连接器、真实
历史证据包和模型适配器仍是后续建设方向。

研究包与揭晓包在物理目录和校验清单上完全分开：`validate` 只接收 `cases/` 下的
研究包，不会定位或读取 `reveals/`；`demo` 才显式接收揭晓包和评估时间。系统
区分观测、发布、版本、采集、截止五个时间。`prospective_capture` 要求在截止前
完成采集；`retrospective_authenticated` 允许事后采集，但必须有同一版本在截止
前已发布的可核验凭据。当前合成案例属于后者，不能冒充前瞻采集或真实历史证据。
当前 pre-alpha 只实现了明确标注的合成凭据验证器；真实资料若在截止后才采集，
会直接拒绝，直到项目接入经评审的档案或签名验证器。供分析或 AI 使用的
`snapshot.json` 只含合格记录；隔离值、无效结论及其来源元数据不会混入快照。

默认不覆盖已有输出目录。确需重跑时可在完整命令末尾加 `--force`；它只接受
空目录或属于同一案例、带 OpenMacroState 标记的旧输出，不授权写入研究包或
揭晓包。

## 欢迎哪些贡献

- 官方宏观数据连接器；
- 历史事件回放与事后评分；
- 资产负债表、传导机制和竞争解释；
- 外部宏观模型适配器；
- 测试、复现、数据许可核查；
- 文档、教程、翻译和社区答疑。

贡献者不需要同时精通经济学与软件工程。Issue 会尽量标注所需技能、预计工作量
和验收标准。核心协议或公共模式变更先走 RFC；普通文档修正和现有接口下的
连接器可以直接提交 Pull Request。

## 许可证

项目原创代码与文档默认采用 Apache-2.0。外部数据不会因此自动变成
Apache-2.0：每个来源必须单独说明许可、转载条件和署名要求。权利不清楚时，
只保留官方链接或使用合成测试数据，不把原始数据提交进仓库。

详细规则以英文版 [README](../../README.md)、
[贡献指南](../../CONTRIBUTING.md)、[治理规则](../../GOVERNANCE.md)和
[数据许可政策](../data-licensing.md)为准。
